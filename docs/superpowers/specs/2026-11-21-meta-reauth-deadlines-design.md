# Meta publishing reauthorization deadlines

Issue [#465](https://github.com/lolotam/POSTORA/issues/465) follows deployed [PR #464](https://github.com/lolotam/POSTORA/pull/464). A revoked native Facebook or Instagram grant can trigger one conditional reconnect write per account attempt. Two deadlines govern that side effect.

1. **Write completion.** Today the timer in `flagRevokedGrant` aborts the signal, but handler cleanup still awaits the writer. Race the writer against an independently settling timeout within the existing budget (at most 5 seconds). On expiry, settle the timeout and abort the signal. Keep one warning path for timeout, thrown failure, rejection or returned storage error. Emit only `meta_publish_reauth_write_failed`, account ID and platform. A successful write and a successful zero-row match both finish quietly. Clear the timer in every outcome and keep a rejection handler attached to the losing promise. An uncooperative writer may finish later. Expiry bounds the handler's wait and never authorizes another write.
2. **Evidence freshness.** Today `pollContainer` passes its overall poll deadline after decoding each response. Immediately before each fetch, sample the injected clock after any sleep. Compute the effective timeout from that same start and available poll budget. Pass the fetcher that duration and the observer the absolute cutoff `start + effectiveTimeout`, including check-once and unlimited-budget polls. A body decoded at or after its cutoff cannot claim the write. A later timely structured `OAuthException` with numeric code 190 and subcode 458 can still claim it. Keep status interpretation, retries and Threads polling intact.
3. **Handler ordering.** The current route fixture releases the blocked write when the healthy destination reaches its publish POST. Give the test sole control of release. Observe successful settlement for that destination while the first account's write is pending, verify the handler still owes a response, then release the write and verify completion. Use synthetic fixtures throughout.

The writer keeps the existing account, post-owner, platform, active-state, reconnect-state and exact `updated_at` predicates. Token matching and evidence classification stay in the existing observer. The change requires no migration, credential change or public API change.
