## Behavior and boundaries

After the existing atomic protected selection commit, the route calls `refreshPageLinkedInstagramPermissions`. The use case reads the server-only bound Facebook User credential and requires its account/platform, credential ID/revision, connection version and capability generation to agree with the committed receipt. A missing or moved authority refuses before any provider request or capability write. No Page-token or browser-provider-token fallback exists.

The permission-read start time and committed generation are captured before provider HTTP. `/v22.0/me/permissions` is bounded by an aggregate eight-second provider budget, four pages, 100 entries per page and a 65,536-byte body limit per response. Continuations reconstruct the approved Graph endpoint using a validated, nonrepeating cursor; supplied next URLs are never followed. The entire response is validated, including string statuses, duplicate scopes, HTTP/provider errors and incomplete pages.

Only a complete successful read supplies authoritative grants. An empty granted set, declined permissions or expired permissions are successful denial evidence; they are not failed reads. Network, malformed, oversized or incomplete results record failed evidence instead of an empty grant. Writes use the existing service-only `write_instagram_account_capability` RPC with the original expected generation and start timestamp. Generation/timestamp refusals are returned as stale, never retried with a newly observed generation. The existing SQL remains responsible for structural ownership, ordering and preserving an established grant after a failed read on the same generation.

Connection success now includes an additive `permissions` result: `{status:"ok",insights_granted:boolean}` or `{status:"failed"|"stale"|"unconfirmed"}`. It describes this permission observation, not rollback of the already committed connection. An ambiguous read/write cannot confirm insights. The route records a sanitized `system_logs` outcome; audit failure leaves the permission result unconfirmed without replaying the account commit. Tokens, raw driver/provider errors and provider URLs never enter that result or audit metadata.

The existing protected HTTP helper adds an optional bounded-body read for this actual consumer. Other callers keep their prior body behavior. Its transport deadline still covers headers and body; the bounded reader cancels/releases its stream when the provider ignores the abort signal.
