# Postora Partner API v1 — Developer Documentation

Base URL: `https://api.postora.cloud/functions/v1/partner-api`

All v1 routes live under the `/v1` prefix, e.g. `GET /v1/accounts`. The alias `POST /functions/v1/partner-api` is frozen (see `deprecations.md`).

Contract and tooling: the canonical OpenAPI 3.1 document is `docs/api/openapi.yaml` and the derived Postman collection and environments are described in `docs/api/README.md`.

## Implementing with an AI agent

Hand the agent (Claude Code, Cursor, Codex, Copilot) exactly two files: **`AGENT-CONTEXT.md`** from this directory — every page below in reading order, preceded by the rules and traps an implementation gets wrong, plus endpoint, scope, error and event tables derived from the code — and **`docs/api/openapi.yaml`**, the machine contract to generate a client from. `llms.txt` is the same rules with links, for tools that index it.

Both are generated by `scripts/generate-agent-context.ts` and never hand-edited; CI fails when the committed copy is not what the generator produces. After editing any page here, regenerate:

```sh
deno run --allow-read --allow-write scripts/generate-agent-context.ts
```
